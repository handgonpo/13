
## 1.  정규화란?
	데이터를 중복 없이 정리하고, 나중에 에러 없이 쉽게 관리할 수 있게 테이블 구조를 만드는 
	규칙입니다. 즉, 하나의 테이블에 섞여 있는 역할들을 각자 맡은 역할별 테이블로 나누는 
	설계 규칙을 말합니다.

쉽게 말하면:
- ❌ 학생 정보 + 반 정보 + 성적 정보 + 연락처 정보를  
    한 테이블에 다 넣어두면 → 나중에 관리가 너무 힘들어짐
    
- ✅ 그래서 “이 정보는 누구 이야기인가?”를 기준으로 테이블을 나눕니다.
    
👉 이 나누는 기준이 바로 정규화 규칙 (1NF → 2NF → 3NF) 입니다.


---
## 2. ❓ 왜 필요할까요?

1️⃣ 중복 데이터가 너무 많아짐
- 같은 학생 이름, 같은 반 선생님이 계속 반복됨
    
2️⃣ 수정할 때 오류가 생김
- 김선생님 이름을 바꾸려면 → 모든 행을 다 찾아서 수정해야 함
- 하나라도 빼먹으면 데이터 불일치 발생
    
3️⃣ ERD를 그릴 수가 없음
- 역할이 섞여 있으면 “이 테이블은 뭐하는 테이블인가?” 설명이 안 됨
    
👉 그래서 ERD를 제대로 그리려면 정규화가 거의 필수입니다.

## 3. 비정규형(혼합) 테이블 예시
| 학생ID | 학생이름 | 반이름 | 반선생님 | 연락처                          | 과목명 | 점수  |
| ---- | ---- | --- | ---- | ---------------------------- | --- | --- |
| 1    | 철수   | 1반  | 김선생님 | 010-1111-1111, 010-2222-2222 | 수학  | 90  |
| 1    | 철수   | 1반  | 김선생님 | 010-1111-1111, 010-2222-2222 | 영어  | 85  |
| 2    | 영희   | 1반  | 김선생님 | 010-3333-3333                | 수학  | 95  |
| 3    | 민수   | 2반  | 박선생님 | 010-4444-4444                | 영어  | 88  |
이 테이블은 **학생 테이블인가요? 성적 테이블인가요? 반 테이블인가요?**  
→ ❌ 전부 섞여 있음

## 4. 제1정규형 (1NF) – 원자값(더 이상 나눌 수 없는 값)만 허용 

📖 규칙:
- 각 칸(컬럼)은 하나의 값만 가져야 합니다.
- 즉, 한 셀에 두 개 이상의 정보가 있으면 안됩니다. 쉼표로 여러 값 ❌

|학생ID|학생이름|반이름|반선생님|연락처|과목명|점수|
|---|---|---|---|---|---|---|
|1|철수|1반|김선생님|010-1111-1111|수학|90|
|1|철수|1반|김선생님|010-2222-2222|수학|90|
|1|철수|1반|김선생님|010-1111-1111|영어|85|
|1|철수|1반|김선생님|010-2222-2222|영어|85|
|2|영희|1반|김선생님|010-3333-3333|수학|95|
|3|민수|2반|박선생님|010-4444-4444|영어|88|
✅ 연락처 한 셀에 하나만 넣었어요 → 원자값만 존재 → 1NF 완료
	데이터베이스가 이해할 수 있는 형태가 됨

## 5. 제2정규형 (2NF) – 부분 종속 제거 
(복합키의 일부에만 의존하는 정보는 분리)

📖 현재 테이블의 핵심:
- 한 학생은 여러 과목을 들음
- 👉 기본키 = (학생ID, 과목명)

❓ 여기서 질문
	학생 이름은 과목이 바뀌면 달라지나요?
답변:
- ❌ 아니요
- 👉 학생이름, 반이름, 연락처는 학생ID만 알면 충분

###### 📄 학생 테이블 (학생 자체 정보만)
| 학생ID | 학생이름 | 반이름 | 연락처           |
| ---- | ---- | --- | ------------- |
| 1    | 철수   | 1반  | 010-1111-1111 |
| 1    | 철수   | 1반  | 010-2222-2222 |
| 2    | 영희   | 1반  | 010-3333-3333 |
| 3    | 민수   | 2반  | 010-4444-4444 |
###### 📄 성적 테이블 (학생ID + 과목명 기준)
|학생ID|과목명|점수|
|---|---|---|
|1|수학|90|
|1|영어|85|
|2|수학|95|
|3|영어|88|
학생 정보 ≠ 성적 정보 
	학생 정보와 성적 정보를 분리합니다.

✅ 과목 관련 정보만 남기고 나머지 정보는 학생 테이블로 이동  
→ 부분 종속 제거 → 2NF 완료

- 이 표의 기본키는 `(학생ID, 과목)`이에요. 왜냐하면 같은 학생이 여러 과목을 들으니까요.
- 그런데 `학생이름`은 `과목`이랑은 아무 상관이 없잖아요?
“학생 이름은 과목에 따라 바뀌는 것도 아닌데 같이 있을 필요가 없습니다.
그래서 학생의 이름은 학생ID랑만 연결합니다.

💡 핵심 규칙: 복합키일 때, 그 일부에만 의존하는 정보는 따로 떼어내기!
	즉, 과목과 상관없는 정보는 성적 테이블에 있으면 안 된다

## 6. 제3정규형 (3NF) – 이행 종속 제거
	A → B → C 구조면 분리

현재 문제
	학생 테이블에 `반이름`, `반선생님`이 함께 있음

📖 규칙:
- `반이름` → `반선생님` 이므로, 
- `반선생님`은 중간 컬럼(반이름)을 거쳐야만 알 수 있습니다. 그래서 분리해야 합니다.
- 반 정보를 따로 빼서 `반이름`과 `반선생님`을 연결!
- 즉 반 선생님은 학생이 아니라 반의 속성
###### 📄 반 테이블
|반이름|반선생님|
|---|---|
|1반|김선생님|
|2반|박선생님|
✅ 이제 모든 테이블이 역할별로 완전히 정리되었습니다.
- 학생은 반이름만 알고
- 반이름으로 반선생님을 찾음
→ 3NF까지 완료!

## 7. 최종 정규화 완료: 4개의 테이블로 나눠짐
#### 1️⃣ 학생 테이블
| 학생ID | 학생이름 | 반이름 |
| ---- | ---- | --- |
| 1    | 철수   | 1반  |
| 2    | 영희   | 1반  |
| 3    | 민수   | 2반  
학생 테이블: 학생의 고유 정보 (ID, 이름, 반)

#### 2️⃣ 연락처 테이블
| 학생ID | 연락처           |
| ---- | ------------- |
| 1    | 010-1111-1111 |
| 1    | 010-2222-2222 |
| 2    | 010-3333-3333 |
| 3    | 010-4444-4444 |
연락처 테이블:  학생 1명이 여러 연락처를 가질 수 있으므로 분리 (1:N 관계)

#### 3️⃣ 성적 테이블
| 학생ID | 과목명 | 점수  |
| ---- | --- | --- |
| 1    | 수학  | 90  |
| 1    | 영어  | 85  |
| 2    | 수학  | 95  |
| 3    | 영어  | 88  |
성적 테이블: 복합키 `(학생ID, 과목명)` 기반으로 성적 저장

#### 4️⃣ 반 테이블
| 반이름 | 반선생님 |
| --- | ---- |
| 1반  | 김선생님 |
| 2반  | 박선생님 |
반 테이블: 반이름을 기준으로 반선생님을 구분

## 8. ERD 개념 정리

#### ERD를 쉽게 말하면?
	ERD(Entity Relationship Diagram)는 데이터베이스에 어떤 표(테이블)들이 있고,  
	그 표들이 어떻게 서로 연결되어 있는지를 그린 지도입니다.
쉽게 말해서:
	엑셀 파일 여러 장을 책상 위에 펼쳐놓고 “이 표랑 이 표는 어떤 기준으로 이어지지?”를  
	그림으로 표현한 것이라고 생각하면 됩니다.

---
🔹 엔티티(Entity)란?
	하나의 역할을 가진 정보 묶음’이며, DB에서는 보통 하나의 테이블이 됩니다.

▪️ 학생 엔티티
- 학생 한 명에 대한 정보
- → 학생ID, 이름, 반

▪️ 연락처 엔티티
- 학생의 연락 수단
- → 전화번호

▪️ 성적 엔티티
- 학생이 과목에서 받은 점수
- → 학생ID + 과목 + 점수

▪️ 반 엔티티
- 반 자체의 정보
- → 반이름, 반선생님

즉 엔티티를 요약하면 이 테이블은 무엇에 대한 설명인가? 라는 질문에 한 문장으로 답이 나오면 → 엔티티

---
🔹 관계(Relationship)란?
	한 엔티티의 데이터가 다른 엔티티와 어떻게 연결되는지’를 의미합니다
	
쉽게 말하면:
1️⃣ 한 학생은 전화번호를 여러 개 가질 수 있다
- 학생 1명
- 연락처 여러 개
👉 1 : N 관계

2️⃣ 한 학생은 여러 과목의 성적을 가진다
- 학생 1명
- 성적 여러 개
👉 1 : N 관계	

3️⃣ 한 반에는 여러 학생이 소속된다
- 반 1개
- 학생 여러 명
👉 1 : N 관계

관계는 말로만 존재하는 게 아니라, DB에서는 실제 컬럼으로 구현됩니다.
👉 그 컬럼이 바로 외래키(Foreign Key)입니다.

외래키(FK)를 초보자 말로 풀면
	다른 테이블의 기본키(PK)를 가져와서 서로 연결해 주는 컬럼입니다

---
###### 📖 정규화 정리
| 정규화 단계             | 규칙 설명          | 쉽게 말하면…                                  |
| ------------------ | -------------- | ---------------------------------------- |
| 1NF (제1정규형)        | 원자값만 허용        | 한 칸에는 값 하나만 써야 해요                        |
| 2NF (제2정규형)        | 부분 종속 제거       | 주인공이 아닌 정보는 따로 빼요                        |
| 3NF (제3정규형) ...... | 이행 종속 제거 ..... | 기본키를 거치지 않고 다른 컬럼을 통해서만 알 수 있는 정보는 분리해요. |

---
### 정규화 결과: 역할별로 나뉜 엔티티(테이블)
	정규화를 거치면, 하나의 큰 표가 아니라 역할이 명확한 여러 테이블**로 나뉘게 됩니다.

정규화 후 엔티티 목록
1. `Student`: 학생 기본 정보 (`student_id`, `name`, `classroom`)
2. `Phone`: 연락처 (1명의 학생이 여러 연락처 가능)
3. `Score`: 성적 정보 (`student`, `subject`, `score`)
4. `Classroom`: 반 정보 (`class_name`, `teacher`)

👉 이 각각이 ERD에서 말하는 엔티티(Entity)입니다.  
👉 그리고 Django에서는 각각 하나의 모델(Model)이 됩니다.

## 9. Django 모델 (정규화 결과 반영)

아래 코드는 정규화된 ERD 구조를 그대로 Django 모델로 옮긴 것입니다.
`Django 모델`
```python
# models.py

from django.db import models

# 1. 반 정보 테이블
class Classroom(models.Model):
    class_name = models.CharField(max_length=10, unique=True)  # 예: 1반, 2반
    teacher = models.CharField(max_length=50)  # 예: 김선생님
	"""
	의미
	- 반이라는 개념 자체를 하나의 테이블로 분리   
	- 반 이름만 알면 → 담임 선생님을 알 수 있음
	- 3NF(이행 종속 제거)의 결과
	"""

    def __str__(self):
        return f"{self.class_name} ({self.teacher})"


# 2. 학생 테이블
class Student(models.Model):
    name = models.CharField(max_length=50)
    classroom = models.ForeignKey(
	    Classroom, 
	    on_delete=models.CASCADE, 
	    related_name='students'
	)
	"""
	의미
	- 학생은 반에 소속됨 
	- 그래서 classroom은 ForeignKey
	"""
    def __str__(self):
        return f"{self.name} - {self.classroom.class_name}"


# 3. 연락처 테이블
class Phone(models.Model):
    student = models.ForeignKey(
        Student,
        on_delete=models.CASCADE,
        related_name='phones'
    )
    number = models.CharField(max_length=20)
	"""
	의미
	- 학생 1명은 전화번호를 여러 개 가질 수 있음  
	- 그래서 연락처를 학생 테이블에 넣지 않고 분리
	"""
    def __str__(self):
        return f"{self.student.name}: {self.number}"


# 4. 성적 테이블
class Score(models.Model):
    student = models.ForeignKey(
        Student,
        on_delete=models.CASCADE,
        related_name='scores'
    )
    subject = models.CharField(max_length=30)
    score = models.PositiveIntegerField()

    class Meta:
        unique_together = ('student', 'subject')  # 복합키 대체
	"""
	의미
	- 학생 + 과목이 하나의 성적  
	- 같은 학생이 같은 과목을 두 번 가질 수 없음 
	- Django에서는 복합 PK 대신 `unique_together`로 구현
	"""
    def __str__(self):
        return f"{self.student.name} - {self.subject}: {self.score}"
```

`Classroom`	: 반이름(class_name)과 반선생님(teacher)을 저장
`Student`	: 학생이름(name)과 소속 반(classroom)을 연결
`Phone`	: 학생의 연락처 — 학생당 여러 개 가능 (1:N)
`Score`	: 학생과 과목, 점수를 저장 — 학생ID + 과목이 고유 (복합키 역할)

---
### 1️⃣ Django 필드 타입(Field Type) 정리
|필드 타입|의미|주로 언제 쓰나|
|---|---|---|
|`CharField`|**짧은 문자열 저장**|이름, 과목명, 전화번호, 코드값|
|`PositiveIntegerField`|**0 이상 정수**|점수, 수량, 나이|
|`ForeignKey`|**다른 테이블과의 관계(1:N)**|소속, 주인 관계|
|`Model`|DB 테이블 하나를 의미|클래스 = 테이블|

### 2️⃣ CharField / IntegerField 괄호 안 옵션 뜻 : models.CharField(max_length=50)
| 옵션           | 의미      | 설명               |
| ------------ | ------- | ---------------- |
| `max_length` | 최대 글자 수 | DB 컬럼 크기 + 필수 옵션 |

###### `models.PositiveIntegerField()`
|옵션|의미|
|---|---|
|(기본)|0 이상 정수만 허용|

### 3️⃣ ForeignKey 옵션 완전 해설
```python
models.ForeignKey(
    Classroom,
    on_delete=models.CASCADE,
    related_name='students'
)
```

###### 🔹 ForeignKey 첫 번째 인자
|위치|의미|
|---|---|
|`Classroom`|**어떤 테이블을 참조하는지**|
→ DB에서는 `classroom_id` 컬럼 생성됨

###### 🔹 `on_delete` 옵션
|값|의미|언제 쓰나|
|---|---|---|
|`CASCADE`|부모 삭제 시 자식도 삭제|소속 관계|
|`PROTECT`|부모 삭제 금지|핵심 데이터 보호|
|`SET_NULL`|부모 삭제 시 NULL|선택 관계|
|`DO_NOTHING`|아무것도 안 함|거의 안 씀|
여기서는
> 반이 삭제되면 → 그 반의 학생도 함께 삭제  

###### 🔹 `related_name`
|의미|역할|
|---|---|
|역참조 이름|부모 → 자식 접근 시 사용|
예시:
```python
classroom.students.all()
student.phones.all()
student.scores.all()
```
없으면 기본값은 `student_set`, `phone_set` 처럼 자동 생성됨

### 5️⃣ `class Meta` 안 옵션 설명

```python
classMeta:
    unique_together = ('student','subject')
```

|옵션|의미|
|---|---|
|`unique_together`|**복합 UNIQUE 제약조건**|

📌 의미:
- 같은 학생 + 같은 과목 조합은 **1번만 가능**
- DB 레벨에서 중복 차단

💡 최신 Django에서는 이렇게도 씀:
```python
constraints = [
    models.UniqueConstraint(
        fields=['student','subject'],
        name='uniq_student_subject'
    )
]
```

### 6️⃣ 한 줄 요약
> 🔹 CharField → 문자열
> 🔹 **ForeignKey** → 다른 테이블과의 1:N 관계
> 🔹 **on_delete** → 부모 삭제 시 행동
> 🔹 **related_name** → 역참조 이름
> 🔹 **unique / unique_together** → 중복 방지 규칙

ERD 기호를 한국어로 읽는 공식

`| —— O<` 해석
> **왼쪽( | ) = 반드시 1개**  
> **오른쪽( O< ) = 0개 이상 여러 개**

👉 이걸 “누가 누구를 몇 개 가질 수 있나”로 바꿔 말하면:
> 왼쪽 1개는 기준 주체 
> 오른쪽 여러 개는 그에 속한 데이터들


1️⃣ Classroom | —— O< Student
	하나의 Classroom(반)에는 학생이 0명 이상 있을 수 있다  
	각 Student(학생)는 반드시 하나의 Classroom에 속한다

2️⃣ Student | —— O< Phone
	한 학생은 전화번호를 0개 이상 가질 수 있다  
	각 전화번호는 반드시 한 학생에 속한다

3️⃣ Student | —— O< Score
	한 학생은 성적 기록을 0개 이상 가질 수 있다  
	각 성적 기록은 반드시 한 학생에 속한다
